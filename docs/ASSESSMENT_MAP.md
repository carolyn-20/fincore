# Assessment traceability map

| # | Assessment | Project implementation / evidence |
|---|---|---|
| 01 | Financial customer frontend | `apps/web`; responsive login, wallet balances, transfer form; capture screenshots and browser demo. |
| 02 | Financial REST APIs | Express routes in `apps/api/src/routes.js`; OpenAPI and Postman docs; add endpoint-level Supertest coverage. |
| 03 | Double-entry ledger database | `schema.sql`, `services/ledger.js`; immutable-by-application ledger posting; verify constraints and ledger balance. |
| 04 | Financial identity and authorization | bcrypt password hashes, JWT, role middleware, audit trail; MFA simulation is a documented extension point. |
| 05 | Python financial calculations | FastAPI service currently scores risk with Decimal; extend with fee/interest/statement calculation endpoints and rounding tests. |
| 06 | FastAPI risk analytics | `/v1/risk/score`, synthetic transaction velocity flags, pytest tests. |
| 07 | Transfer consistency engine | Transactional row locks, balance check, unique idempotency key, paired ledger entries. Run concurrency tests against PostgreSQL. |
| 08 | Payment and notification integrations | Local test payment-intent adapter and signed/deduplicated webhook endpoint. Email/SMS are sandbox adapter extension points; external provider test credentials are not included. |
| 09 | Containerized financial stack | Dockerfiles and Compose for web, API, Postgres, Redis, FastAPI. Add worker service when asynchronous jobs are implemented. |
| 10 | Git and change governance | GitHub workflow and semantic commit guidance; branch protection/review must be enabled in repository settings. |
| 11 | Secure financial CI/CD | CI workflow runs API, risk and frontend checks. Image/dependency/secret scanning, approvals and rollback require repository/environment configuration. |
| 12 | Ledger and payment testing | Basic unit tests included. Add DB integration tests for concurrent transfers, webhook replay, reversal and settlement failure. |
| 13 | Financial API contracts | Swagger generated by Express route docs is a TODO; Postman collection provided as a starter. Expand lifecycle/error/webhook contract docs. |
| 14 | Secure deployment and recovery | Compose simulated environment. Cloud HTTPS, encrypted backups, restore drills and production monitoring require actual hosting/configuration and evidence. |
| 15 | Financial incident simulation | Schema supports event inbox, audit and risk alerts. Runbooks and seeded incident scenarios are documented as next implementation tasks. |

**Important:** This repository is a substantial runnable foundation, not a claim that every assessment acceptance criterion has already been fully met. Follow `KNOWN_LIMITATIONS.md`, complete the listed extensions, run the tests, and capture evidence before submission.
